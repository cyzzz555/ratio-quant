# 开发任务排期（不承诺时间）

| 顺序 | 工作分解 | Done定义 | 依赖 |
|---|---|---|---|
|P0|确定API产品线；公开exchangeInfo、K线、WS可用性探测；动态规格和能力报告|真实可复现的只读报告、未验证标注、无私钥|官方文档、网络|
|P1A|Monorepo、Python/React骨架、DB迁移、Decimal模型、Parquet、测试|本地可运行、无真实下单代码路径|P0|
|P1B|先一套策略TrendPullback研究实现、基准回测；另两策略插件接口|可复现回测、费用模型与数据hash|P1A|
|P1C|完成MeanReversion、EventDriven研究插件及可用时点模型|三策略独立评分、事件源断供不乱下单|P1B|
|P2|WebSocket、定时补全、市场双层扫描、Regime、两阶段信号及通知|断线/缺口时安全降级，信号状态与回放一致|P1|
|P3|PaperBroker、仓位/风险纯函数、订单状态机、审批模拟、止损/止盈|全部离线风控/订单异常测试通过|P2|
|P4|认证+2FA、API权限分离、只读账户对账、故障恢复与审计|沙盒演练、无live下单权限|P3|
|P5|经用户单独明示授权且具备交易资格后接真实订单|小额受控实盘监测与真实成本验证|P4+批准|
|P6|完整PWA、K线回放、每周研究/版本审批、全链路告警|综合安全、灾难恢复测试通过|P5或单独可并行子项|

**迭代目标**：尽早提供可验证正确性的一小段代码，而不是一次性生成数万行无测试业务逻辑。Codex每完成一个阶段必须报告新增文件、运行命令、成功/失败测试、开放问题和不可执行能力。
